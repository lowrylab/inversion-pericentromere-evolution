# Reproducibility

## Included provenance

The repository includes the exact production models, SHA256 hashes, the 700-run
baseline manifest and parameter table, compact derived baseline tables, figures,
the Arm B 300-task manifest, local smoke outputs, and the scripts used to
analyze and validate them. Raw production outputs are excluded to keep the
repository reviewable; the manifests identify their expected paths and seeds.

## Three reproducibility levels

**Code reproducibility** means that the exact model files, hashes, parameters,
manifests, analysis scripts, and compact inputs are preserved here.

**Computational reproducibility** means that the simulations can be rerun with
SLiM 5.1 on a compatible local machine or HPCC environment and that task
outputs pass the same completion and accounting checks. A site-specific SLiM
module and cluster filesystem are still required for HPCC execution.

**Scientific robustness** asks whether conclusions persist across alternative
migration, selection, dominance, DFE, initial-frequency, and seed choices. The
completed maintenance baseline is one parameterized result; it is not by
itself a robustness analysis.

## Baseline

From the repository root, use SLiM 5.1:

```sh
./scripts/run_paired_baseline.sh
python3 scripts/analyze_baseline.py
Rscript scripts/make_baseline_figures.R
```

The included `results/maintenance_baseline/` files are the completed run and
should be treated as the reference derived results. Re-running the simulation
requires enough local storage for raw outputs.

## Arm B on HPCC

1. Copy this checkout to MSU project or scratch storage.
2. Run `hpcc/check_hpcc_environment.sbatch` and record the hostname, module,
   executable path, SLiM version, CPU, and memory.
3. Submit `hpcc/submit_hpcc_smoke.sbatch`; it creates six paired tasks at
   m=0, 0.01, and 0.05.
4. Copy the six HPCC outputs into `validation/mechanistic_smoke/hpcc_smoke/`
   and run `python3 hpcc/compare_smoke.py`.
5. Inspect `sacct` elapsed time, MaxRSS, CPU time, and failures. Set production
   `--time` and `--mem` from those measurements, with modest safety margin.
6. Submit `hpcc/submit_mechanistic_array.sbatch` with the existing manifest.
7. Run `python3 hpcc/check_completion.py`; do not interpret production results
   until all 300 tasks are complete and successful.
8. Run `python3 scripts/analyze_arm_b.py` from the repository root.

The HPCC smoke and production runs were not executed in the current local
environment because no MSU login, SLURM controller, or module tree was
available. No HPCC completion or resource-use claim is made here.

## Clean-checkout test

The fast validation is designed to run from a clean checkout:

```sh
python3 -m py_compile scripts/*.py hpcc/*.py
python3 scripts/ci_validate.py
```

These checks require no files outside the repository. SLiM-dependent
simulation and R figure regeneration remain explicitly documented external
dependencies.

## Figure regeneration

The baseline PNGs in `figures/maintenance_baseline/` are generated by
`scripts/make_baseline_figures.R` from the compact analysis tables. The Arm B
analysis entry point writes endpoint and trajectory tables plus QA output; it
does not silently replace the baseline figures.
